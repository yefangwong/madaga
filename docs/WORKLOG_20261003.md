## 🏛️ 二、 五大核心架構突破 (Core Architectural Breakthroughs)

### 1. 企業 Schema 零外洩與地端內網剛性熔斷 (`BRD-CSP-SEC-007`)
* **痛點**：企業引進 AI 最大阻力在於資安長 (CISO) 擔心資料資產外洩。
* **突破**：Text-to-SQL 通道強制實施「外網請求熔斷器（Outbound Air-Gap Circuit Breaker）」。推論端點必須是私有 IP / localhost（Ollama、vLLM）；若配置公網域名，系統微秒級剛性阻斷，拋出 `ERR_SECURITY_OUTBOUND_SCHEMA_LEAK_FORBIDDEN`，達成最高級別資料不出廠承諾。

### 2. 地端算力 ＝ AI 時代的「電信 OSS 通訊資源」
* **映射**：在電信 OSS 中，基地台與光纖屬於最底層的 **Resource Layer**，服務層從不直接硬連某台設備，而是向資源層申請電路配額。
* **實踐**：將地端 GPU 顯存與推論槽位抽象為 TMF SID `net.yefangwong.csp.domain.resource`（`tbl_res_provider`, `tbl_res_compute_node`）。業務邏輯單元透過 `IComputeResourceProxy` 與 `CapabilityRouter` 申請推論槽位，防止多用戶同時提問把 GPU 打到 CUDA OOM 當機。

### 3. 汲取經典 IBM Catalog 精神：自訂「算力頻寬 (Compute Bandwidth Tiers)」
* **精神傳承**：借鏡經典電信 Catalog 介面五大精神：
  1. **左樹右表 (Catalog Tree)**：左側是方案與資源樹，右側是詳細規格與 Tab。
  2. **版本演進 (Versioning)**：`Ver. 001` 配搭「新增版本」與 `Efftv Date`，Schema 與算力變更不粗暴覆蓋，歷史可追溯。
  3. **動態特徵值 (CharacteristicSpec)**：以 EAV 表格自訂屬性（如：`TokenBandwidth=500`、`VRAM=8GB`、`Slot=4`）。
  4. **成員組合 (Composite)**：Text-to-SQL 服務由文字化 ERD + 語法約束 FSM + 算力實例複合而成。
  5. **驗證門禁 (Validation)**：發布前執行獨立「驗證」按鈕，全綠燈方可上線。
* **流量整形 (Token Shaping)**：透過電信級漏桶演算法，依租戶或角色購買的頻寬等級（如 Bronze: 20 T/s, Gold: 100 T/s）進行順暢排隊分流。

### 4. 邊緣硬體熱插拔橫向擴充 (Scale-Out to 輝達小電腦 DGX Spark)
* **願景**：企業算力隨業務成長擴充，不需要換大伺服器，只需在廠區內網「隨插即用插上一台**輝達小電腦（NVIDIA DGX Spark / Jetson Orin）**」！
* **代碼呼應**：專案既有的 [`NvidiaDgxSparkDriver.java`](file:///Users/yefangwong/Documents/GitHub.nosync/madaga/csp/csp-base/src/main/java/net/yefangwong/csp/common/proxy/compute/NvidiaDgxSparkDriver.java) 與 [`CapabilityRouter.java`](file:///Users/yefangwong/Documents/GitHub.nosync/madaga/csp/csp-base/src/main/java/net/yefangwong/csp/common/proxy/compute/CapabilityRouter.java) 已經具備 `VRAM > 16GB` 自動分流至 DGX Spark 節點的能力，軟硬一體、無縫拓展。

### 5. 架構自洽性四維稽核閉環 (`AUDIT_REPORT_CSP_PORTAL_WEB_20261003`)
* **成果**：在動手改代碼前完成極限稽核，精準揪出 `doQueryBySQL` 幽靈函式、安全路由脫鉤（`/manage/emp` vs `/employee/**`）與 `SseServiceImpl` 硬編碼 Key `"1"` 三大致命硬傷，省下數天無謂踩坑。
